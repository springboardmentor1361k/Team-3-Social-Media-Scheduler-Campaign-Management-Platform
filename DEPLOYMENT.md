# SocialPilot — Deployment Guide

Free-tier deployment stack:
| Component | Service | Cost |
|---|---|---|
| Frontend (Next.js) | Vercel | Free |
| Backend API (FastAPI) | Render Web Service | Free |
| Celery Worker | Render Background Worker | Free |
| Celery Beat | Render Background Worker | Free |
| PostgreSQL | Neon | Free |
| Redis (Celery broker) | Upstash | Free |
| MongoDB | Atlas M0 | Free (already done) |
| Media Storage | AWS S3 | Free tier |

---

## Step 1 — Neon PostgreSQL

1. Go to https://neon.tech and sign up
2. **Create a new project** (name it `socialpilot`)
3. Neon auto-creates a database. Open the project dashboard.
4. Click **Connection Details** → choose **Pooled connection** → copy the string

It looks like:
`
postgresql://user:password@ep-xxx-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
`

5. **Keep this URL** — you will add it to Render and your local .env as DATABASE_URL

> The ?sslmode=require part is mandatory for Neon — do not remove it.

### Run Alembic migrations against Neon (once)

`ash
cd backend
# Set DATABASE_URL in your local .env to the Neon pooled URL
source venv/bin/activate     # or venv\Scripts\activate on Windows
alembic upgrade head
`

## Step 2 — Upstash Redis

1. Go to https://upstash.com and sign up
2. Click **Create Database**
3. Name it `socialpilot-redis`, choose the **same region as your Render services** (Singapore or US East)
4. Keep **TLS enabled** (default)
5. Once created, open the database → **Details** tab
6. Copy the **Redis URL** — it starts with 
ediss:// (double s = TLS)

`
rediss://default:xxxxxxxx@xxx-xxxxx.upstash.io:6379
`

7. **Keep this URL** — add it to Render as REDIS_URL

> **Important**: SocialPilot is already configured to detect 
ediss:// and enable SSL automatically in celery_worker.py.

## Step 3 — Render (Backend API + Celery Services)

### 3a — Push your code to GitHub

Make sure your repo is on GitHub (or GitLab/Bitbucket). The 
ender.yaml file at the project root will auto-configure all 3 services.

`ash
git add .
git commit -m "Add render.yaml, Dockerfile, deployment config"
git push origin main
`

### 3b — Connect Render to your GitHub repo

1. Go to https://render.com → sign up → **New** → **Blueprint**
2. Connect your GitHub account and select your repo
3. Render will detect 
ender.yaml and show 3 services to create:
   - socialpilot-api (Web Service)
   - socialpilot-celery-worker (Background Worker)
   - socialpilot-celery-beat (Background Worker)
4. Click **Apply** — Render will start building from the Dockerfile

### 3c — Set Environment Variables in Render Dashboard

For each of the 3 services, go to **Environment** and set these variables.
Variables marked sync: false in 
ender.yaml must be set manually.

**Set these on ALL 3 services (api + worker + beat):**

| Variable | Value |
|---|---|
| DATABASE_URL | Your Neon pooled URL (with ?sslmode=require) |
| MONGODB_URL | Your Atlas connection string |
| MONGODB_DB | socialpilot |
| REDIS_URL | Your Upstash 
ediss:// URL |
| TOKEN_ENCRYPTION_KEY | Generate: python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())" |

**Set these on the socialpilot-api service only:**

| Variable | Value |
|---|---|
| ALLOWED_ORIGINS | https://your-app.vercel.app (fill in after Step 4) |
| AWS_ACCESS_KEY_ID | Your AWS key |
| AWS_SECRET_ACCESS_KEY | Your AWS secret |
| AWS_REGION | e.g. p-south-1 |
| S3_BUCKET_NAME | e.g. socialpilot-media |
| S3_PUBLIC_URL | e.g. https://socialpilot-media.s3.ap-south-1.amazonaws.com |
| FACEBOOK_APP_ID | From Meta Developer Console |
| FACEBOOK_APP_SECRET | From Meta Developer Console |
| FACEBOOK_REDIRECT_URI | https://socialpilot-api.onrender.com/api/v1/oauth/facebook/callback |
| INSTAGRAM_REDIRECT_URI | https://socialpilot-api.onrender.com/api/v1/oauth/instagram/callback |
| LINKEDIN_CLIENT_ID | From LinkedIn Developer |
| LINKEDIN_CLIENT_SECRET | From LinkedIn Developer |
| LINKEDIN_REDIRECT_URI | https://socialpilot-api.onrender.com/api/v1/oauth/linkedin/callback |
| TWITTER_API_KEY | From X Developer Portal |
| TWITTER_API_SECRET | From X Developer Portal |
| TWITTER_BEARER_TOKEN | From X Developer Portal |
| TWITTER_REDIRECT_URI | https://socialpilot-api.onrender.com/api/v1/oauth/twitter/callback |
| GOOGLE_CLIENT_ID | From Google Cloud Console |
| GOOGLE_CLIENT_SECRET | From Google Cloud Console |
| GOOGLE_REDIRECT_URI | https://socialpilot-api.onrender.com/api/v1/oauth/youtube/callback |

> SECRET_KEY is auto-generated by Render (set to generateValue: true in render.yaml). Copy it from the pi service and manually paste the **same value** into the worker and beat services so all 3 share the same JWT secret.

### 3d — Verify deployment

After the build completes (5–10 minutes first time):

`
https://socialpilot-api.onrender.com/          → {"status": "ok"}
https://socialpilot-api.onrender.com/docs      → Swagger UI
`

## Step 4 — Vercel (Frontend)

### 4a — Install Vercel CLI and deploy

`ash
npm install -g vercel
cd frontend
vercel
`

Follow the prompts:
- Link to existing project or create new
- Framework: Next.js (auto-detected)
- Root directory: ./ (already inside rontend/)

### 4b — Or deploy via Vercel Dashboard (no CLI needed)

1. Go to https://vercel.com → **New Project**
2. Import your GitHub repo
3. Set **Root Directory** to rontend
4. Framework preset: **Next.js** (auto-detected)
5. Click **Deploy**

### 4c — Set Environment Variable in Vercel

After deploy, go to your project → **Settings** → **Environment Variables**:

| Variable | Value |
|---|---|
| NEXT_PUBLIC_API_URL | https://socialpilot-api.onrender.com |

Click **Save** then **Redeploy** (top right) to apply the variable.

Your frontend URL will be: https://your-project-name.vercel.app

### 4d — Update ALLOWED_ORIGINS on Render

Go back to Render → socialpilot-api service → **Environment**:

Update ALLOWED_ORIGINS:
`
https://your-project-name.vercel.app
`

Render will auto-redeploy the service.

- **Vercel**: Settings → Domains → Add domain → follow DNS instructions
- **Render**: Service → Settings → Custom Domain

## Troubleshooting

| Symptom | Fix |
|---|---|
| API returns 500 on startup | Check Render logs — usually a missing env var |
| SSL SYSCALL error on DB | Neon URL must end with ?sslmode=require |
| Celery worker can't connect to Redis | REDIS_URL must be the 
ediss:// URL from Upstash (with double s) |
| Celery tasks silently not running | Check worker service logs in Render — not the API logs |
| Frontend shows CORS error | ALLOWED_ORIGINS on Render must exactly match your Vercel URL (no trailing slash) |
| MODULE_NOT_FOUND on Vercel | Make sure Root Directory is set to rontend in Vercel project settings |
| Render free service takes 30s to respond | Free tier spins down after 15 min idle — first request wakes it up. Normal. |
| TOKEN_ENCRYPTION_KEY error | Must be a valid 32-byte base64 Fernet key. Generate fresh with the Python one-liner above. |
